Visão Geral do Sistema

Fluxo: Chrome Extension → Nginx (SSL) → Uvicorn (FastAPI) → MySQL + IA providers

Backend
  • FastAPI + Python 3.12
  • Uvicorn com 1 worker
  • Porta interna: 127.0.0.1:8000
  • Systemd service: saleia.service
  • JWT auth (PyJWT + bcrypt)
Frontend
  • HTML/CSS/JS vanilla (sem framework)
  • Servido pelo próprio FastAPI
  • Dashboard: /dashboard
  • Cenário: /cenario/{meeting_id}
  • Interceptor global JWT no fetch
Banco de Dados
  • MySQL remoto: fast5342_AV3D
  • SQLite local: data/metricas.db (métricas rolling 24h)
  • Conexão MySQL via PyMySQL
Proxy / SSL
  • Nginx em 80/443
  • Certbot SSL (Let's Encrypt)
  • Domínio: api.saleia.app.br
  • Proxy pass: 127.0.0.1:8000
Fluxo de uma reunião
1

Extensão Chrome captura áudio

Content script detecta Google Meet → grava fragmentos de áudio a cada ~4s.

2

POST /audio-transcricao

Fragmento enviado para Groq Whisper Large v3 → retorna texto transcrito.

3

POST /tempo-real

Transcrição + contexto enviados para agente_tempo_real.analisar_fragmento() → chama chamar_ia_async() com fallback.

4

RAG (base de conhecimento)

Antes de chamar a IA, busca contexto similar via embedding OpenAI text-embedding-3-small. Injeta no prompt.

5

Resposta para a sidebar

Dicas retornadas pela IA → sidebar da extensão Chrome exibe em tempo real.

6

Finalização: POST /recapitulacao-manual

Ao encerrar a reunião → gera recapitulação, DISC, diagnóstico financeiro e salva no MySQL.

Circuit Breaker
  • Abre após 3 falhas consecutivas (variável AI_PROVIDER_FAILURES_TO_OPEN)
  • Cooldown: 60 segundos (variável AI_PROVIDER_COOLDOWN_SECONDS)
  • Durante cooldown, provedor é pulado automaticamente
  • Alerta Telegram enviado ao abrir o circuit breaker
Contadores em memória

Resetam a cada restart do serviço. Visíveis na aba Monitor do dashboard.

  • chamadas_total / sucesso / falha
  • fallbacks — quantas vezes caiu para o próximo provedor
  • por_provedor[name].sucesso / falha / total_ms
  • Provedor sem chave configurada → incrementa falha (desde V.1.4.14)
RAG — Base de Conhecimento
  • Arquivo: agent/base_conhecimento.py
  • Embedding: text-embedding-3-small via OpenAI (1536 dimensões)
  • Cache em memória carregado no primeiro acesso
  • 49+ transcrições indexadas no banco MySQL
  • Busca cosine similarity para top-k contextos similares
  • Falha silenciosa: se embedding falhar, IA responde sem contexto RAG
Transcrição de áudio
  • Provider: Groq (whisper-large-v3)
  • Configurado via GROQ_API_KEY
  • Endpoint: POST /audio-transcricao
  • Alternativa anterior (desativada por quota): OpenAI Whisper

9. sem budget             → type=question  (capacidade de investimento)

Arquitetura Multiagente em Tempo Real V.1.4.36

O endpoint POST /tempo-real agora dispara 4 agentes especializados em paralelo via asyncio.gather(return_exceptions=True):

# orquestrador.py — fluxo principal
async def analisar_fragmento_multi(transcricao_parcial, historico, perfil_disc_atual,
        mapa_financeiro, resumo_vivo, diagnostico_atual, historico_scores, eventos,
        skill_context="", client_context="") -> dict:

    # RAG buscado uma única vez, compartilhado entre todos os agentes
    rag = await _buscar_rag(transcricao_parcial)
    client_context += rag

    coach, disc, finance, closer = await asyncio.gather(
        analisar_coach(..., skill_context, client_context),
        analisar_disc(...),
        analisar_finance(...),
        analisar_closer(...),
        return_exceptions=True
    )
    # _safe() converte Exception em {} para degradação graceful
    return _mesclar(_safe(coach), _safe(disc), _safe(finance), _safe(closer))

Follow-up Inteligente V.1.4.37

Fluxo: POST /relatorios/{mid}/followups/gerar → lê memória + DISC + score → gerar_e_salvar_followups() → IA gera 3 mensagens → agenda_inteligente(score) calcula timing → 3 INSERTs no MySQL.

# Agenda inteligente — server-side, determinístico, sem risco de alucinação de datas
def agenda_inteligente(score: int) -> list[dict]:
    if score >= 65:   # hot
        return [{"dias": 1, "canal": "whatsapp"}, {"dias": 4, "canal": "email"}, {"dias": 10, "canal": "linkedin"}]
    elif score >= 35: # warm
        return [{"dias": 3, ...}, {"dias": 7, ...}, {"dias": 15, ...}]
    else:              # cold
        return [{"dias": 2, ...}, {"dias": 5, ...}, {"dias": 14, ...}]

Banco de Dados
MySQL — Tabelas
  • usuarios — auth, perfil, plano, reset_token
  • reunioes — meeting_id, dados da sessão
  • base_conhecimento — textos + embeddings para RAG
  • relatorios — recapitulações, DISC, score history
  • sales_memories — memórias extraídas por reunião
  • meeting_status — flags de reunião (ganha, etc.)
  • playbooks — roteiros de reuniões ganhas
  • skills — módulos de skill com instruções
  • client_profiles — perfis de clientes
  • client_meetings — vínculo cliente↔reunião
  • followups — mensagens de follow-up por canal
SQLite — Métricas e Estado Compartilhado
  • Path: data/metricas.db
  • Tabela metricas_historico: ts, banco_latencia, reunioes_ativas, chamadas_ia, falhas_ia — retenção 24h, escrita a cada 60s
  • Tabela teste_provedores: pid, ok, ts, detalhe — resultado do último teste de conexão por provedor (upsert atômico via ON CONFLICT DO UPDATE)
  • Multi-worker: com --workers 2, estado in-memory (_ultimo_teste) é isolado por processo. A tabela teste_provedores é o único estado compartilhado entre workers — todos leem/escrevem via metricas_historico.py
  • Criação automática no startup via criar_tabela_metricas() e criar_tabela_teste_provedores()
Migrations automáticas no startup

A função migrar_colunas_usuarios() em main.py roda no startup e adiciona colunas faltantes na tabela usuarios sem recriar a tabela. Seguro para produção.

Troubleshoot
Serviço não sobe
# Ver erro de startup
journalctl -u saleia -n 50 --no-pager
tail -50 /opt/saleia/logs/saleia.log
# Testar manualmente
cd /opt/saleia && venv/bin/uvicorn api.main:app --host 127.0.0.1 --port 8001
Monitor retorna 401

O fetch interceptor global injeta o token automaticamente. Se falhar:

  • Verificar se saleia_token existe no localStorage
  • Verificar se o token não expirou
  • Fazer logout e login novamente
DeepSeek não aparece no Monitor (0/0)
  • Verificar ordem em data/ai_provider_order.json na VPS
  • Se Anthropic/OpenAI estiverem antes, resolvem tudo antes do DeepSeek ser tentado
  • Corrigir ordem via SSH (ver seção Roteador de IA)
  • Verificar se DEEPSEEK_API_KEY está no .env
Provedor retorna 429 (quota)
  • OpenAI: verificar quota em platform.openai.com
  • Anthropic: verificar créditos em console.anthropic.com
  • O roteador faz fallback automaticamente após 3 falhas (circuit breaker)
  • Groq (transcrição): verificar limits em console.groq.com
RAG não funciona (embedding 401)
  • A chave OPENAI_API_KEY está inválida ou expirada
  • Atualizar via painel admin → APIs → OpenAI → Salvar
  • Testar: ssh root@37.27.214.33 "cd /opt/saleia && venv/bin/python3 -c \"from openai import OpenAI; import os; from dotenv import load_dotenv; load_dotenv('.env'); r=OpenAI(api_key=os.environ.get('OPENAI_API_KEY')).embeddings.create(model='text-embedding-3-small',input='teste'); print('OK',len(r.data[0].embedding))\""
Gemini retorna 404 (modelo descontinuado)
# Atualizar modelo no .env da VPS
ssh root@37.27.214.33 "sed -i 's/GEMINI_MODEL=.*/GEMINI_MODEL=gemini-2.5-flash/' /opt/saleia/.env && systemctl restart saleia"
502 Bad Gateway (workers zombie)

Uvicorn aceita a conexão TCP mas retorna resposta vazia após ~2,5 dias de uptime. O Nginx recebe "Empty reply from server" e repassa o 502 ao Cloudflare.

  • Diagnóstico: curl -v --resolve api.saleia.app.br:443:37.27.214.33 https://api.saleia.app.br/health → "Empty reply from server"
  • Fix imediato: ssh root@37.27.214.33 "systemctl restart saleia"
  • Prevenção permanente: RuntimeMaxSec=86400 no /etc/systemd/system/saleia.service — reinício automático diário (já aplicado)
  • Após editar a unit: systemctl daemon-reload && systemctl restart saleia
Serviço fica em stop-sigterm (timeout 90s)

Uvicorn não finaliza limpo — ocorre quando há conexões pendentes. Causa comum: 2 workers com estado compartilhado.

  • VPS configurada com --workers 1 para evitar isolamento de contadores
  • Se ocorrer: systemctl kill -s SIGKILL saleia && systemctl start saleia
